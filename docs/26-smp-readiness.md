## 1. 设计回顾：M10.0–M10.8 的验收判据

设计早已成文（`06-smp.md`，性能优先口径），**本文不重复设计**，只把每一步的
**退出条件**提炼成可核对的判据。出处一律是 `06-smp.md` §13 的分阶段计划表
（`:416-430`）。

### 1.1 性能口径（`06-smp.md` §1 `:12-29`）

| 编号 | 指标 | 目标 | 出处 |
|---|---|---|---|
| **G1** | CPU 密集 N 线程墙钟加速比 | N=2 ≥ **1.8**；N=4 ≥ **3.5** | `06-smp.md:16` |
| **G2** | 4 核 IPC 聚合吞吐 | ≥ **2M 次/秒** | `06-smp.md:17` |
| **G3** | 一核做长 I/O 时另一核吞吐 | 下降 < **5%** | `06-smp.md:18` |
| **G4** | `--smp 1` 单核性能 | 相对今天退化 < **2%** | `06-smp.md:19` |
| **G5** | 无竞争自旋锁加解锁 | < **40** 周期 | `06-smp.md:20` |
| ★ 负向对照 ★ | 同样 N 线程但亲和性全设 CPU 0 | 加速比必须回落 **≈1** | `06-smp.md:21` |

### 1.2 分阶段判据（`06-smp.md` §13 `:420-430`）

| 阶段 | 内容 | 退出条件（判据） |
|---|---|---|
| **M10.0 观测先行** | 每 CPU 统计骨架、锁争用计数器、看门狗心跳（**此时仍是单核**） | 单核跑通，计数器有值（为后面的判断准备工具） |

| **M10.7 争用驱动的细粒度化** | 按 M10.0 的计数器拆最热的锁；评估 ticket/queued lock | G1(N=4) ≥ **3.5**；p99 不退化 |
| **M10.8 真机** | 等 M9 的 AHCI/virtio-blk 之后（现在只有 ATA PIO + 两个虚拟机） | — |

### 1.3 ★ 判据本身的三处不一致（审计发现，需要先拍板）★

同一个指标在三处写法不同。**M10.1 要"定下 G4 的基线"，所以这三处必须先统一**，
否则"退化多少算不退化"在执行时会各说各话：

| 指标 | `01-milestones.md` | `06-smp.md` §1 | `06-smp.md` §12 |
|---|---|---|---|
| `--smp 1` 单核回归 | **不退化超过 5%**（`01-milestones.md:18`） | **< 2%**（`:19` G4） | **RPC ≤ 6300 周期**（`:400`） |
| N=2 加速比 | ≥ **1.7**（`:18`） | ≥ **1.8**（`:16`） | ≥ **1.7**（`:397`） |
| N=4 加速比 | ≥ **3.0**（`:18`） | ≥ **3.5**（`:16`） | ≥ **3.0**（`:397`） |

三者是**三种不同的口径**（百分比 / 绝对值周期数 / 更松的阈值），不是笔误。
`06-smp.md:23-25` 解释了为什么 §1 把 G1 定在 3.5 而不是 3.0（"定高一点，
达不到时才知道该去查什么"），而 §12 的测试表用的是 1.7/3.0。
**建议**：把 §1 定为"目标值"、§12 定为"验收门槛"，并在
`01-milestones.md:18` 明确它引用的是哪一个。

## 4. 第一步建议：M10 的最小可验证起点

### 4.1 建议：**M10.0 + M10.1 合并成一个"仍跑 `--smp 1`"的落地刀**

**不要**从"AP bootstrap + 自旋锁 + 让两个核跑起来"起步。理由不是保守，
而是**设计已经论证过顺序**（`06-smp.md:444-451`）：

> 分阶段依然是安全的，只是顺序换成"**先把结构建对，再上核**"。

具体理由有三条，都能用本文的证据支撑：

1. **分配器与页表在多核上不是"变慢"，是"内存被写坏"**（C3/C4/C5）。
   `06-smp.md:47-50` 明写这一条要**最先**修；而在**单核**下修它同样正确、
   且有完整自检覆盖 —— 这是唯一能"改完立刻知道对不对"的窗口。
2. **A3/X2 决定"第二个核能不能起来"**：`g_syscall_percpu` 与 TSS 是全局单例，
   per-CPU 化之前让 AP 进内核 = 用别人的内核栈。S4/S5 说明这一刀很薄。
3. **A4 是"重构会静默改变语义"的那一类**：让出退化成空操作是 `f12e39b`
   辛苦修好的（"被饿 10 倍"），它的判据建立在**全局**队列上。
   必须在**单核、且 bench 有基线**的时候把等价判据重新推导出来，
   否则它会以"偶发性能问题"的形式出现，而不是以失败断言的形式出现。

**建议的最小切口（顺序即优先级）**：

| 序 | 内容 | 理由 |
|---|---|---|
| 1 | `struct fe_cpu` + `this_cpu()` + GS 基址 + 每 CPU TSS（**仍单核**） | 所有其它 per-CPU 化的载体；S5 说汇编改动接近零；B5/B9 说 TSS 与 LAPIC 状态是"第一个 AP 上第一条指令"就踩的坑 |
| 2 | **PMM 页帧批次 + kheap per-CPU slab 缓存**（C3/C4），以及 A8/F10 里"**连 `cli` 都没有**"的那几处 | "内存会被写坏"，且它同时是性能目标本身（§15 第 4 条 `:503` 建议 M10.1 就做）。`06-smp.md:47-50` 明确要求它**最先**修 |
| 3 | per-CPU 运行队列 + `current` + `need_resched`（A1/A2/A5/A7/X2）★ **并且同时把"READY→RUNNING"做成原子所有权移交**（§6 `:206-210`） | 热路径必须无全局锁（§13 硬规则 `:453-460`）。★ **原子移交不能推迟**：A2 说今天"摘链 + 置 RUNNING"是两步，per-CPU 队列一旦落地而所有权仍非原子，**同一线程被两核执行**就从"不可能"变成"必然" |
| 4 | ★ **重新推导 A4 的让出判据**（并把 `g_st_kept_lower`/让出代价固化成断言） | A4 的判据建在**全局**队列的"唯一可运行"上。若只把队列改成 per-CPU 而不动它，**单核 G4 基线（<2%）与多核正确性会互相矛盾**——这是 M10.1 里唯一"会静默改变语义"的一刀，必须在有 bench 基线的单核窗口里做完 |
| 5 | per-CPU 节拍与 TSC 权威时间（E1/E3），**并先做 E4 的 TSC 可信性探测** | 与 §7 的"节拍降级为每 CPU 调度输入"一致。E4 决定"时间能不能跨核信"，建议提前到 M10.1（它是 sleep/超时/clock_gettime 的共同前提） |
| 6 | 冷子系统加锁：页表树（C5）、VMA 表、资源池（F10）、句柄表（F9）、共享线记账（B4）、IRQ 表与向量槽（B10）、对象映射 bump（F11） | 它们不在热路径上，一把粗锁就够（§9 `:290`）。★ 但 F9/F10 的**生命周期**问题（lookup 拿裸指针、认领无保护）要在 AP 上线**之前**解决 |

★ **本轮审计对设计的一处修正建议** ★ —— `06-smp.md` §9 的"子系统加锁清单"
（`:292-303`）**没有"VMM / 页表树"这一行，也没有"VMA 表"这一行**。
但 C5（`next_table` 的 check-then-allocate）与 §2 第 8 行只覆盖的"TLB 陈旧"
是**两个不同的问题**：IPI shootdown 解决"表项陈旧"，**锁**解决"树结构被写坏"。
建议在 §9 补两行，并把 C5 归到 **M10.2**（不能等到 M10.5）。

### 4.2 可证伪判据（含**反向对照**）

判据必须能**证明机制真的生效**，而不只是"没崩"（`06-smp.md` §12 `:408-410`
把这称作"整张表的灵魂"）。第一步（仍 `--smp 1`）的判据：

**正向**

1. `--smp 1` 下**全部自检 0 失败**（今天有 24 条汇总行，见 README/`01-milestones.md`）。
2. **G4 基线被钉下来并写进文档**：bench 四组数字与改造前**逐项对照**。
   ★ 注意 §1.3 的三处不一致 —— 必须先选定口径（建议取
   `06-smp.md:19` 的 **< 2%**，`01-milestones.md:18` 的 5% 作为上限兜底）。
3. **结构性判据（可静态检查）**：`g_current` / `g_runq` / `g_ticks` / `g_syscall_percpu`
   在源码中**不再以单例形式出现**，`this_cpu()` 有唯一实现。
4. 每 CPU 统计骨架有值（M10.0 的退出条件，`06-smp.md:422`）。

**反向（这一条比正向重要）**

5. ★ **必须先能复现"坏"，才能证明"修好了"** ★
   在 per-CPU 分片/加锁**之前**，用一个"两个执行流并发分配"的探针
   （单核上可用两个内核线程在被抢占点交错，模拟并发）**复现**至少一种损坏：
   PMM 返回同一帧 / kheap 返回同一对象 / `next_table` 产生孤儿帧。
   若复现不出来 ⇒ 说明探针无效，**先修探针**，不要宣称"加了锁就对了"。
   这与项目"能证明机制失效的那条测试，才让通过的测试有意义"
   （`06-smp.md:410`）是同一条纪律。
6. **A4 的反向对照**：把"让出退化成空操作"的等价判据固化成一个**带阈值的断言**
   （例如 `g_st_kept_lower` 与"让出代价 ≤ 4.00 节拍/次"，见 `sched.c:576` 的实测上界）。
   per-CPU 化之后该断言**必须仍然通过**；不通过就说明语义被改坏了。
7. **不能退化的东西要单独列**：`06-smp.md:400` §12 的"单核回归"要求
   **RPC ≤ 6300 周期**且自检全 0 —— 建议把它作为第 2 条的绝对值补充。

### ★ 一处需要更正的说法 ★

"MSI 的目的 CPU 固定给 BSP（记录在 `14-interrupt-semantics.md` §8）"这个说法
**两处都不准确**，核实结果：

- **`docs/14-interrupt-semantics.md` §8 里没有任何 MSI 目的 CPU / BSP 的字样**
  （该节讲的是"MSI-X 表项由内核代写""两个开关""怎么证明真的走了 MSI-X"）。
  它只有 `:122` 的公式"地址 = `0xFEE00000 | (dest_apic_id << 12)`"。
  实测输出里的 `addr 0xfee00000`（`docs/14:327`）是因为**今天只有一个 CPU**。
- 遗留的**真实记录**在 `docs/12-drivers.md:113`：
  "⬜ 遗留：MSI 的目的 CPU 现在固定写给 BSP，等 K10 SMP 落地后才谈 per-CPU 投递"，
  以及 `README.md:51`："今天全是单核假设（"杀别的线程"、MSI 目的 CPU 固定给 BSP）"。
- **机制上也不是"写死 BSP"**：`irq.c:647-649` 取的是 `fe_lapic_id()`
  （**调用者所在 CPU**），注释 `:646` 自己写着"目的固定为**本 CPU**（今天单核；
  SMP 时这里要按 IRQ 亲和性选）"。单核上 `fe_lapic_id()` 恰为 BSP(=0)，
  所以"固定给 BSP"是**单核退化的结果**，不是常量 0。IOAPIC 同理（`irq.c:290`）。
