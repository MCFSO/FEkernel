# 多核（SMP）设计

> ★ **本文按"性能优先"写** ★：目标是让多核真正吃满，
> 而不是"能跑在 4 个核上"。所以热路径的设计原则是
> **不共享 → 不需要锁 → 天生可扩展**，而不是"用锁保护共享"。
>
> 多核在整个性能路线图里的位置、以及为什么它**不是**第一优先级，
> 见 `07-performance-roadmap.md`（磁盘路径差三个数量级，多核差 3.5 倍）。
> 本文只解决多核这一格。

## 1. 多核要买到什么（性能口径）

| 编号 | 指标 | 目标 | 说明 |
|---|---|---|---|
| **G1** | CPU 密集型 N 线程的**墙钟加速比** | N=2 ≥ **1.8**；N=4 ≥ **3.5** | 3.5/4 = 87.5% 效率。达不到就说明热路径上还有共享 |
| **G2** | 4 核上的 **IPC 聚合吞吐** | ≥ **2M 次/秒** | 比单核极限（~500k/s）高 4 倍以上 |
| **G3** | 一个核做长 I/O 时，另一个核的吞吐 | 下降 < **5%** | "真并发"的直接证据 |
| **G4** | `--smp 1` 的单核性能 | 相对今天退化 < **2%** | 多核不许把单核变慢 |
| **G5** | 无竞争的自旋锁加解锁 | < **40** 周期 | 锁的成本地板，bench 单独测 |
| ★ **负向对照** ★ | 同样 N 个线程，亲和性全设 CPU 0 | 加速比必须回落 **≈1** | 没有它，"加速比 3.5"无法区分真并行与计时错误 |

**为什么 G1 定 3.5 而不是 3.0**：热路径一旦做到"不共享"，扩展比就只受
内存带宽与调度器开销限制；定 3.0 等于默认自己会留一个全局串行点。
**定高一点，达不到时才知道该去查什么**（先查伪共享，再查全局锁，最后查内存带宽）。

延迟类指标（单个 syscall、单次 RPC 的周期数）**不作为本文的目标**：
它们由 `07-performance-roadmap.md` 的主线 B 负责（fastpath、直接栈切换），
多核在这里只要求**不把它们弄坏**（G4）。

## 2. 今天的内核建立在哪些单核假设上（实地勘察）

不是泛泛而谈"要加锁"，而是逐条列出**代码里真实存在的假设**。这张表就是工作清单。

| # | 假设 | 代码位置 | 在 SMP 上会怎样 | 修法 |
|---|---|---|---|---|
| 1 | **cli 就是互斥** | 全内核 `fe_irq_save/restore`（sched/ipc/object/resource/protect/irq…） | `cli` 只关**本 CPU** 的中断，别的 CPU 照进不误 → 所有临界区同时失效 | 引入真正的自旋锁；`cli` 降级为"防本 CPU 中断重入"的辅助手段（§4） |
| 2 | **"每 CPU"的东西是全局的** | `g_syscall_percpu`（`syscall.c:44`，`gs:0/gs:8`）；`g_tss_block`（`gdt.c:15`，rsp0 + 6 份 I/O 位图） | 第二个 CPU 的 syscall 入口会用**别的线程的内核栈**（`gs:8`）→ 立刻栈错乱崩溃；TSS 的 `rsp0` 也只能是一个值 | 每 CPU 一份（§5）。**GS 基址机制已经存在**，改动很小 |
| 3 | **调度器状态是全局的** | `sched.c:29-40`：`g_runq[32]` / `g_ready_mask` / `g_current` / `g_sleep_list` / `g_zombies` / `g_all` / `g_need_resched` / `g_next_id`；idle 线程只有一个 | 切换是**最热的路径**，一把全局锁会直接吃掉多核收益 | per-CPU 运行队列（§6） |
| 4 | **分配器不需要同步** | `kernel/mm/pmm.c`、`kernel/mm/kheap.c` 里**连 `cli` 都没有**——它们靠"调用者处于不可抢占上下文"（syscall 入口 SFMASK 清 IF）这个隐含前提 | 两个 CPU 同时分配 → 位图/空闲链直接损坏；而且这个前提在 SMP 上双重不成立 | 各加一把锁（§9）。这是**最容易被忽略、后果最严重**的一条：它不是"效率问题"，是"内存会被写坏" |
| 5 | **IPC 有两条全局空闲链** | `ipc.c:27-35`：`g_msg_free_list`（64 条消息）、`g_ep_free_list`（端点池） | **每条 RPC 都要动它们两次**（分配消息 + 分配回复端点）→ 全局串行点，且没有锁保护 | 每 CPU 消息缓存 + 每端点锁（§11） |
| 6 | **中断都进 BSP** | `irq.c:158`、`time.c:115` 都传 `fe_lapic_id()` 当目标；LAPIC 定时器只在 BSP 上启动 | 所有中断挤在一个核；AP 上的线程**不会被时间片抢占**（没有本地节拍） | 每 CPU LAPIC 定时器 + IOAPIC 定向（§7） |
| 7 | **节拍是一个全局计数器** | `time.c:28`：`static volatile u64 g_ticks` | N 个 CPU 各自跑定时器 → `g_ticks` 以 N 倍速前进，所有 sleep 都变短 | 节拍降级为**每 CPU 的调度输入**；时间仍以 TSC 为权威（§7） |
| 8 | **页表只在当前上下文改** | `mm/vmm.c` 的 map/unmap/destroy | 同一任务的两个线程在两个核上跑时，一个核改页表，另一个核的 TLB 仍指着旧映射 | 惰性 generation + 按需 IPI shootdown（§8） |
| 9 | **线程只可能在一个核上跑** | `sched.c` 的状态机（`RUNNING` 是一个普通赋值） | 两个核可能同时把同一个线程从就绪队列里摘出来 → **同一线程被两个 CPU 执行**，栈与现场互相踩 | 所有权转移改成原子操作（§6） |

第 4 条值得单独强调：**PMM 与 kheap 里没有任何同步**，它们今天能正确工作，
靠的是"syscall 入口清 IF → 内核代码不可抢占"这条链条。
多核把这条链条从"足够"变成"完全不成立"，而症状是**内存随机损坏**，
不是崩溃在出错的地方。所以这一条要**最先**修，而不是等到拆锁阶段。

## 4. 原语：内核的第一把锁

内核现在**没有任何自旋锁**，所以这一步是从零建原语，必须一次做对。

```c
typedef struct {
    volatile u32 locked;        /* 0 = 空闲，1 = 已持有 */
    u32 owner_cpu;              /* 仅调试：逆序检测与死锁诊断用 */
    u32 _pad[14];               /* 独占一个 cache line */
} FE_ALIGNED(64) fe_spinlock_t;
```

获取用 test-and-set + `pause` + 指数退避；释放用一次 store-release。

三种形态，**用途不能混**：

| 形式 | 语义 | 用在哪 |
|---|---|---|
| `fe_spin_lock(l)` | 只互斥，不动中断 | 只在**保证不会被中断处理程序碰到**的数据上 |
| `fe_spin_lock_irqsave(l, flags)` | 关本 CPU 中断 + 拿锁 | ★ 默认选择 ★ 数据可能被 ISR 访问时**必须**用这个 |
| `fe_spin_lock_irq(l)` | 关中断 + 拿锁，解锁时开中断 | 确定调用点中断是开着的短临界区 |

★ **规则 1（最重要）**：**中断处理程序会碰的锁，必须用 `irqsave` 形式。**
否则同 CPU 自死锁：拿到锁 → 中断到来 → ISR 抢同一把锁 → 自旋等自己。
这是 SMP 移植里最常见的一类死锁，而且它**只在特定时序下发生**，测试很难稳定复现。
落地办法：每把锁声明一个 `fe_lock_irq_scope` 标记，调试构建里断言"ISR 只获取标了 `IRQ` 的锁"。

★ **规则 2**：**锁顺序必须成表。** 给每类锁一个层级号，调试构建里记录本 CPU
的持锁层级，发现"低层级里拿高层级"就立刻报错并打印两个调用点。
这比事后分析一个死锁现场便宜一个数量级——**死锁的现场里没有任何信息能告诉你顺序是什么**。

★ **规则 3**：**持锁期间不得睡眠、不得调用可能睡眠的函数**（`kmalloc` 若将来会等待、
`fe_sched_*`、任何 IPC）。这一条要写成注释贴在锁的 API 上，因为违反它的代码
看起来完全正常。

**成本预算（G4）**：无竞争的加解锁应当是"一次原子 RMW + 两次编译器屏障"，
目标 < 40 周期。bench 要**单独测它**，因为它是所有其它数字的地板。

**为什么不用 ticket lock 起步**：ticket lock 保证 FIFO、无饥饿，但每次获取都要
"原子读 next + 原子写 next"，低竞争下比 TAS 慢。先用 TAS + 退避，把 ticket 作为
可选实现留着，**用 §12 的争用计数器决定要不要换**（不靠猜）。

## 5. 每 CPU 数据

```c
struct fe_cpu {
    /* ★ 前 16 字节必须与今天的 gs:0 / gs:8 布局完全一致 ★
     * 这样 syscall.asm 一行都不用改（见下）。 */
    u64 user_rsp;                     /* gs:0  —— 暂存用户 RSP */
    u64 kernel_rsp;                   /* gs:8  —— 当前线程内核栈顶 */
    struct fe_cpu *self;              /* gs:16 —— this_cpu() 用 */

    u32 id;                           /* 逻辑序号 0..N-1 */
    u32 apic_id;
    u32 online;
    u32 _pad0;

    struct fe_tss_block tss;          /* 每 CPU 的 TSS：rsp0 + 6 份 I/O 位图 */
    u16 tss_selector;

    struct fe_thread *current;
    struct fe_thread *idle;
    struct fe_runqueue rq[FE_THREAD_PRIO_LEVELS];
    u32 ready_mask;
    volatile u32 need_resched;

    u64 ticks;                        /* 本 CPU 的节拍（调度用） */
    u64 idle_ticks;
    u64 tlb_gen_seen;                 /* §8 的惰性失效 */

    /* 统计与诊断（每 CPU，避免伪共享：热字段分开、结构按 64 字节对齐） */
    u64 switches;
    u64 lock_spins;                   /* 本 CPU 花在自旋上的循环数 */
    u64 ipi_sent, ipi_recv;
} FE_ALIGNED(64);

extern struct fe_cpu g_cpus[FE_MAX_CPUS];     /* 静态数组，N ≤ 64（与 ACPI 上限一致） */
u32 fe_cpu_count(void);                        /* 已上线的核数 */
#define this_cpu()  ((struct fe_cpu *)fe_read_gs(16))
```

### GS 基址的零成本迁移 ★

今天的 `syscall.asm` 约定：

```
gs:0 = 暂存用户 RSP
gs:8 = 当前线程内核栈顶
```

**新布局把 `struct fe_cpu` 的开头 16 字节就定义成这两个槽**，于是：

- `syscall.asm` **一行都不用改**；
- `fe_syscall_percpu` 这个全局结构体消失，`fe_syscall_set_kernel_stack()` 改成
  `this_cpu()->kernel_rsp = rsp`；
- AP 上线时只需要 `wrmsr(GS_BASE, &g_cpus[i])` —— 而这件事
  `fe_syscall_msr_init(entry, percpu)` **已经在做了**。

这是"当初把 GS 当每 CPU 结构用"这个决定的红利：多核支持在系统调用入口上
是零汇编改动。

`this_cpu()` 用 `%gs:16` 读 self 指针。**不**用"编译器 `__seg_gs` 相对寻址"：
那需要非标准的编译器支持，而 clang 在 freestanding 下对它的支持不保证；
一次 `mov` 换来的可移植性更值。

### TSS 必须每 CPU

`rsp0`（从 ring3 中断进来时切到哪个内核栈）**天然是每 CPU 的**——
CPU 0 上的中断必须用 CPU 0 当前线程的栈。

I/O 位图也跟着走：位图**必须落在 TSS 限长之内**（CPU 是相对 TSS 基址读它的），
所以不能"全系统共享一份位图，各 TSS 指过去"。代价是
`6 份 × 8193 字节 ≈ 48 KiB/CPU`（6 是 `fe_tss_block` 里预烘焙的 I/O 位图槽数）。
4 核 192 KiB，可以接受；核数再多就该改成"每任务动态分配位图 + 切换时拷入本 CPU 的 TSS"
（那时拷 8 KiB 比 48 KiB 的常驻更划算）。**现在不做**，理由写在 §14。

GDT 仍然是**一张**（GDTR 是每 CPU 的寄存器，但可以都指向同一张表），
只是里面要放 N 个 TSS 描述符；每个 CPU 在早期初始化里 `ltr` 自己的选择子。

## 6. 调度：per-CPU 运行队列

**选型：每 CPU 一套运行队列，不是"全局队列 + 全局锁"。**

理由是热路径：`fe_sched_maybe_switch` 在**每次系统调用和每次中断返回**时都会跑。
全局队列意味着这把锁的获取频率等于系统调用频率（今天 118 周期的路径），
它会成为第一个把多核收益吃干净的地方。

结构变化：

- `g_runq[32]` → `this_cpu()->rq[32]` + `this_cpu()->ready_mask`；
- `g_current` → `this_cpu()->current`；
- `g_need_resched` → `this_cpu()->need_resched`（其它 CPU 要打断我时用 IPI 置位）；
- **空闲线程每 CPU 一个**（`this_cpu()->idle`），进 `hlt` 前先尝试偷任务；
- `g_all` / 僵尸链改为全局 + 一把锁（它们只在创建/回收时动，不在切换路径上）。

★ **同 CPU 内的队列操作不需要锁**：只有本 CPU 会操作自己的队列，
关本 CPU 中断就足够——**除非别的 CPU 来偷**。所以规则是：

- 入队/出队自己队列：`irqsave` 即可（无锁）；
- 跨 CPU（唤醒、窃取、迁移）：先锁**目标 CPU 的队列锁**，再操作。

★ **执行绪的所有权必须原子转移**：一个 READY 的线程只能被一个 CPU 摘走。
做法是把"从就绪队列取出并置为 RUNNING"做成一次原子操作
（`__atomic_exchange` 抢状态位，抢输的一方重新选）。
没有这一条，两个 CPU 会同时跑同一个线程——**栈互相踩，症状是随机崩溃**，
而且崩的地方和原因隔着十万八千里。

**迁移策略**：只在 `wake` / `create` 时做（`push`：唤醒者把线程放到
"最闲的核"或"上次跑它的核"；`pull`：空闲核从别的核偷）。**切换路径上不做迁移**——
保持它无锁是这个设计的硬约束。

**亲和性** `fe_thread_set_affinity(t, mask)`：三个用途，每个都真实需要

1. **测试确定性**：今天那条"调度轨迹 `AAAAABBBBBCCCCC`"的自检**只在单核上有意义**，
   SMP 下必须把它钉在单核跑（否则它变成一个随机失败的测试，然后被人无视）；
2. **中断局部性**：把驱动线程钉在收该设备中断的核上（§7），缓存命中率差别很大；
3. **实时隔离**：把实时线程和普通服务分开（将来）。

**`hlt` 的经典竞态**：空闲核"检查队列为空 → `sti; hlt`"之间如果另一个核入了队，
`hlt` 就会睡到下一个中断——可能很久。修法是"关中断检查队列 → 有活就不 hlt →
没有就 `sti; hlt` 原子地睡"，并且**所有跨核入队都必须跟一条 reschedule IPI**。
漏掉 IPI 的话症状是"偶发几百毫秒的延迟尖刺"，而不是死锁——更难查。

## 7. 中断、IPI 与时间

**每 CPU 都有自己的 LAPIC 定时器。** 今天的做法（只有一个节拍源）在 SMP 上有两个问题：
AP 上的线程永远不会被时间片抢占；而且节拍计数会变成 N 倍速。

★ **把"节拍"降级为每 CPU 的调度输入，把"时间"留给 TSC** ★
这一刀切下去，`g_ticks` 的 N 倍速问题自然消失：

- `fe_time_ticks()` 不再是一个全局数，而是"本 CPU 的节拍"——它只用来做
  **时间片递减与本地唤醒检查**；
- **所有真实时间仍然走 TSC**（`fe_clock_ns()` 今天已经是 TSC 权威），
  跨核一致，不受节拍数影响；
- 睡眠链表如果保持全局，就需要一把锁 + 跨核唤醒 IPI；**更简单**的做法是
  **睡眠链表也每 CPU 一份**，代价是"在 CPU 0 上 sleep 的线程只能被 CPU 0 唤醒"——
  对定时器语义完全够用（谁睡谁醒），而且顺带把锁去掉了。

**IOAPIC 定向策略**（分两步，先跑通再优化）：

1. 第一步：全部路由到 BSP（与今天一致）。**唯一目的是让多核先正确跑起来**，
   不引入新变量；
2. 第二步：`fe_irq_register` 时按**调用者所在 CPU** 选目标，并提供
   `fe_irq_set_affinity`。理由：中断应当落在"处理它"的那个驱动线程所在的核上，
   否则每次中断都要跨核唤醒（缓存与 IPI 双重代价）。

**电平触发 + EOI**：EOI 必须由**收到该中断的 CPU** 发出。现有代码已经是
"在 ISR 里发 EOI 给自己的 LAPIC"，这一条天然正确——但要在代码里写清楚，
因为一旦有人把 EOI 挪到"统一的中断退出路径"，这条就悄悄错了。

**IPI 向量**：外部设备中断今天用 96..127（`FE_VEC_IRQ`）。IPI 需要自己的向量，
分配如下并写进 `vectors.h`：

| 向量 | 用途 |
|---|---|
| `FE_VEC_IPI_RESCHED` | 叫醒空闲核去偷任务 / 请求重新调度 |
| `FE_VEC_IPI_TLB` | TLB 失效（§8） |
| `FE_VEC_IPI_HALT` | 停机/同步（关核、将来的 reboot 广播） |

## 8. TLB 一致性

今天改页表的人**就是**跑在那个地址空间上的人，所以不需要 shootdown。
SMP 下同一任务的两个线程可以在两个核上，一个核 `unmap` 之后另一个核的 TLB
还留着旧映射——**这是会静默读到已经释放的物理帧的那类 bug**。

方案（两级，先便宜的后贵的）：

1. **惰性失效（先做，零热路径成本）**：每个地址空间一个 `tlb_gen`，
   每次改页表 `tlb_gen++`；每个 CPU 记 `tlb_gen_seen`，在**进入内核**和
   **切换地址空间**时比较，不等就整表刷新（写 CR3 或 `invlpg` 全刷）。
   对"改一次、跑很久"的模式（exec、创建任务）完全够用。
2. **主动 shootdown（需要时再加）**：`unmap` 真的是热路径时，
   向所有可能跑该地址空间的 CPU 发 `FE_VEC_IPI_TLB`，带地址空间与页范围，
   等所有核 ack。这里的复杂度在"等 ack"（是一个屏障，需要每 CPU 的
   ack 计数器 + 自旋/让步）。

**PCID 做，但排在 TLB 正确性之后**：先把换地址空间时的失效做对（惰性 generation →
按需 IPI shootdown），再加 PCID 把"整表刷新"换成"换 PCID"。
性能优先的口径下这一步是值得的——exec/spawn 与 IPC 密集时换地址空间很频繁，
而全刷 TLB 的代价在 IPC fastpath 上会被放大（每次 fastpath 都可能换地址空间）。
它有自己的坑（PCID 复用、INVPCID 语义），所以放在正确性之后而不是之前。

## 9. 子系统加锁清单

粒度一律**先用最粗的能正确工作的**，再由 §12 的争用计数器驱动拆分。

| 子系统 | 今天靠什么 | SMP 方案 | 粒度理由 | 热点？ |
|---|---|---|---|---|
| **PMM**（位图分配） | **什么都没有** | 一把 `irqsave` 锁 | 临界区是"扫描位图 + 置位"，分配频率远低于 syscall | 中 |
| **kheap** | **什么都没有** | 先全局一把锁；`g_search_hint` 改每 CPU | 分配频率高（每次 IPC 都要），是**首批要拆的候选** | **高** |
| **IPC 消息/端点池** | **什么都没有**（两条全局链） | 每 CPU 消息缓存 + 每端点锁 | ★ 每条 RPC 都要动，且天然可分片（按端点） | **最高** |
| **对象/句柄表** | `fe_irq_save` | 每任务一把锁（句柄表是 per-task 的） | 天然按任务分片 | 高 |
| **引用计数** | 已经是 `__atomic_*` | 不动 | 已经对了 | — |
| **调度器队列** | `fe_irq_save` | 每 CPU 队列（同 CPU 无锁）+ 跨 CPU 锁目标队列 | 热路径，必须无全局锁 | **最高** |
| **VFS / ramfs / devfs** | `fe_irq_save` | 一把全局锁 | 挂载表只在初始化变；ramfs 只读 | 低 |
| **protect（区间表）** | `fe_irq_save` | 一把全局锁 | 只在启动登记与违规时写；**检查**是读多写无，用 seqlock 或干脆只读不加锁 | 中（blkd 每次读写都查） |
| **资源池** | `fe_irq_save` | 一把全局锁 | 认领只发生在服务启动时 | 低 |
| **时间** | `g_ticks` 全局 | 每 CPU 节拍 + TSC 权威 | 见 §7 | 高（但无锁） |

★ 注意 `protect` 那一行：**blkd 在每次读写前都调 `fe_protect_check`**，
也就是块设备路径上每次都有一次全局表查询。今天它是"只读一张不变的数组 + `irqsave`"；
SMP 下如果给它加一把普通自旋锁，就把磁盘路径串行化了。
正确做法是**读侧不加锁**（表是单调的：一旦写入就不再改；用发布屏障保证读者
看到的是完整条目），写侧加锁。这是"单调性"这个设计决定在多核上的第二份红利。

## 10. AP 启动序列

分工：**平台的事交给 Limine，OS 的事自己写。** Limine 的 MP 协议会把 AP
拉进长模式（页表已经是内核的）、中断关闭，然后跳到我们设的 `goto_address`，
参数是该核的 `fe_limine_mp_info *`。

BSP 侧：

1. 读 MP 响应：`cpu_count`、`bsp_lapic_id`、`cpus[]`（每个含 `lapic_id`）；
2. 按 LAPIC ID 填 `g_cpus[i]`（id 是逻辑序号，apic_id 是硬件号，两者**必须分开**：
   ACPI 的处理器编号不连续，逻辑编号必须紧凑）；
3. 每个 AP 的 TSS 描述符装进 GDT；
4. 给非 BSP 的每个 `cpus[i]->goto_address = fe_ap_entry`；
5. 等上线计数到齐（**带超时**）。

AP 侧（`fe_ap_entry`）：早、中、晚三段，顺序不能乱

| 顺序 | 做什么 | 为什么在这个位置 |
|---|---|---|
| 1 | 设置自己的内核栈（Limine 给的还是引导器的栈） | 后面任何 C 代码都需要栈 |
| 2 | `wrmsr(GS_BASE, &g_cpus[i])` | 从这一刻起 `this_cpu()` 可用 |
| 3 | 载入同一张 GDT + `ltr` 自己的 TSS 选择子 | `rsp0` 与 I/O 位图必须先于任何 ring3 线程 |
| 4 | 载入内核 PML4（CR3） | 与 BSP 共用内核空间，用户空间部分为空 |
| 5 | `fe_lapic_init()`（本地 LAPIC 已在，MMIO 每 CPU 天然不同）+ 启动本地定时器 | AP 必须能抢占自己的线程 |
| 6 | 建自己的 idle 线程，进入调度器 | 之后这个核就可以被调度了 |
| 7 | 原子 `++` 上线计数；等所有核到齐的屏障 | 屏障之前**不许**碰全局状态 |

**超时处理**：等 3 秒不到齐就**带着实际的核数继续跑**，并且把
"预期 N 核、实际上线 M 核"**明确打印**。绝不静默降级——静默降级会让
"多核没生效"看起来像"性能就是这样"。

**放在什么时候**：在"中断就绪、调度器就绪"之后，**在 `fe_process_start_init` 之前**。
这样 init 拉起的第一个服务就已经可能跑在别的核上。

## 11. IPC Fastpath：多核与微内核的正面冲突

这一节是本文里唯一"用并行度换延迟"的地方，所以要讲清楚。

**现状**：每次 `fe_endpoint_call` 都要

1. 从 `g_msg_free_list` 取一条消息（全局链，64 条）；
2. 创建/取一个回复端点（`g_ep_free_list`，另一条全局链）；
3. 发送 → 阻塞当前线程 → 服务端线程被唤醒 → 处理 → 回复 → 客户端被唤醒。

在单核上，步骤 3 是一次上下文切换（~2200 周期），RPC 总计 5836~6002 周期。
**在多核上，1 和 2 变成全局串行点**（高频、短临界区——正是自旋锁最难受的形状：
抢不到就白烧一个核），而步骤 3 变成"跨核唤醒"，延迟可能比单核**更差**。

**两个方向，都不便宜**：

- **(a) 去掉全局链**：每 CPU 消息缓存（本地命中率高）+ 每端点锁。
  这是纯收益，没有取舍，**先做**。
- **(b) 直接切换（direct switch）**：客户端发起 call 时**不**经过调度器，
  直接把 CPU 交给同核上的服务线程（这正是 seL4 的 IPC fastpath 思路）。
  它能把 RPC 从 ~6000 周期压到 ~2000 量级——但**它要求客户端与服务在同一个核上**。

★ **性能优先的结论：fastpath 是目标，不是"以后再说"** ★
微内核的税就在 IPC 上，而 IPC 的固定成本（6000 周期）里有一大半是
"经过调度器排队"造成的。所以 direct switch 不是可选优化，是
`07-performance-roadmap.md` 主线 B 的核心项，目标 IPC ≤ 2000 周期。

它用并行度换延迟，所以正确用法是**把服务线程钉在收它中断的那个核上**
（§7 第二步），让"同核"成为常态：

```
call 时：
  服务线程 = endpoint->owner_thread
  若 服务线程.affinity 含本核 且 服务线程状态 == READY：
        直接切换（不排队、不发 IPI）→ 延迟大幅下降
  否则：
        常规路径（入队 + 跨核 reschedule IPI）
```

这样得到两份叠加的收益：**中断不打核**（缓存局部性）+ **IPC 走 fastpath**（延迟）。
代价是"服务被钉在某个核上"——这恰好是服务型系统的常见部署方式，
而且用户可以按核数决定钉几个副本（同一服务的多副本各自钉一个核，
这也顺带给出了"IPC 吞吐随核数扩展"的路径）。

## 12. 验证策略：怎么证明它真的并行，而不只是"没崩"

多核最危险的不是"跑不起来"，而是**"看起来跑起来了，其实什么都没并行"**
或者**"90% 的时间是对的"**。所以验证要针对这两件事。

| 测试 | 做法 | 判定（不变量） |
|---|---|---|
| **启动证据** | 日志打印每个 AP 的 LAPIC ID、逻辑编号、上线时间 | 每个核一行；预期核数 == 实际核数，否则明确报警（§10） |
| **加速比 G1** | `bench --smp`：N 个 CPU 密集线程的墙钟时间 vs 1 个线程 | N=2 ≥ 1.7，N=4 ≥ 3.0 |
| ★ **负向对照** ★ | 同样 N 个线程，但亲和性掩码全设成 CPU 0 | 加速比必须回落到 **≈1** |
| **重叠 G2** | 一个核跑 A/B 拷贝的同时，另一个核测 RPC 延迟的 p50/p99 | p99 退化 < 10% |
| **单核回归 G3** | `--smp 1` 跑完整套自检与 bench | RPC ≤ 6300 周期；所有自检 0 失败 |
| **锁成本 G4** | bench 单独测"无竞争加解锁" | < 40 周期 |
| **丢更新** | N 个线程各自累加**自己的**计数器，主线程求和 | 总和**精确**等于期望值（抓丢失的更新，比抓崩溃更灵敏） |
| **争用画像** | 每把锁的 acquire / contended / spin_cycles 计数，退出时打印 top-5 | 决定下一步拆哪把锁（用数据，不猜） |
| **锁顺序** | 调试构建记录每 CPU 的持锁层级，逆序获取立刻报错 | 运行期零违例 |
| **看门狗** | 每 CPU 一个心跳计数；BSP 发现某个核超过 2 秒没动，就打印**所有**核的栈与持锁情况 | 抓死锁与活锁（这是 SMP 唯一有效的现场保留手段） |
| **确定性测试** | 调度轨迹类自检**钉在单核**跑；另加一个"不确定但可判定"的测试 | 前者不许变成随机失败；后者判定的是不变量（如总和） |

★ **负向对照那一行是整张表的灵魂** ★ 没有它，"加速比 2.0"无法区分
"真的并行"和"我的计时错了 / 线程本来就是串行的"。这与前面 protcheck
里"正向对照"是同一个道理：**能证明机制失效的那条测试，才让通过的测试有意义。**

**双环境**：QEMU（`--smp 2/4`，WHPX）与 VirtualBox（`--cpus 2/4`）。
注意 VBox 的中断投递本身就是限流的（49~169 Hz，见 `02-performance.md`），
所以**节拍相关的多核数字只在 QEMU 上采信**，VBox 用来做"行为一致性"对照。

## 13. 分阶段计划（M10）

每一步都有**退出条件**——不满足就不进下一步。

| 阶段 | 内容 | 退出条件 |
|---|---|---|
| **M10.0 观测先行** | 每 CPU 统计骨架、锁争用计数器、看门狗心跳（此时仍是单核） | 单核跑通，计数器有值（为后面的判断准备工具） |
| **M10.1 每 CPU 数据** | `struct fe_cpu` + GS 基址 + **每 CPU 运行队列 / slab 缓存 / 页帧批次 / 消息缓存** + 每 CPU TSS/idle/节拍；**仍然单核运行** | ★ 纯重构 ★ 单核下所有自检 0 失败、bench 不退化（G4 的基线在这里定下来） |
| **M10.2 AP 上线** | Limine MP 启动 AP；boot barrier；冷子系统各给一把锁；**热路径不加锁**（它已经不共享） | 2/4 核全部上线；`--smp 1/2/4` 行为一致；自检全绿；**G1 直接测**（此时就该接近 3.5） |
| **M10.3 IPC fastpath + 直接栈切换** | 同核 direct switch（服务线程钉核）；`switch_to` 不再走完整中断帧；回复端点复用 | IPC 往返 ≤ 2000 周期；**G2 ≥ 2M/s** |
| **M10.4 中断定向 + 亲和性 + tickless** | IRQ 按驱动线程所在核定向；空闲核关本地定时器；`fe_irq_set_affinity` | 打印"IRQ n 落在 CPU k"的证据；**G3 达标** |
| **M10.5 TLB + PCID** | 惰性 generation → 按需 IPI shootdown → PCID 免全刷 | 共享地址空间压力测试跑通；exec/spawn 变快 |
| **M10.6 FPU / SIMD 打开** | CR4.OSFXSR/OSXSAVE + XCR0 + XSAVE 线程上下文；用户态去掉 `-mno-sse` | 用户态能跑 AVX2；memcpy ≥ 60 GB/s；**密码学服务可用**（见 `07-performance-roadmap.md` §6） |
| **M10.7 争用驱动的细粒度化** | 按 M10.0 的计数器拆最热的锁；评估 ticket/queued lock | G1(N=4) ≥ 3.5；p99 不退化 |
| **M10.8 真机** | 等 M9 的 AHCI/virtio-blk 之后（现在只有 ATA PIO + 两个虚拟机） | — |

★ **为什么跳过 BKL，直接建对的结构** ★

上一版设计打算"先一把大锁跑通，再拆"。**性能优先的话这个方案是错的**，理由不是
"拆锁麻烦"，而是：

1. **BKL 存在的理由是"我还不知道哪些数据是共享的"。** 而在这里这个理由不成立——
   §2 已经把 9 处共享逐条定位了。既然知道，就没有理由先造一个必然要拆的东西。
2. **带 BKL 的系统无法验证性能目标。** G1/G2 在 BKL 下必然不达标，
   于是"阶段 2"的验收标准只能是"没崩"——那等于把一个性能目标推迟成了信仰。
3. **大锁最危险的地方是它看起来能工作。** 一旦"跑通了"，拆锁就变成了没有
   明确收益的风险工作，很容易永久留下来。

**而分阶段依然是安全的**，只是顺序换成"先把结构建对，再上核"：

- M10.1 的 per-CPU 数据结构**在单核下就能建好并验证**（此刻它只是
  "唯一那个 CPU 的结构"，行为不变、自检全绿、bench 不退化）；
- 热路径变成 per-CPU 之后，**它本来就不需要锁**——不是"锁变细了"，是"没有共享"；
- 冷子系统（VFS、protect、资源池）各给一把普通自旋锁，它们不在热路径上，
  对性能没有影响，**不需要也不应该为它们设计什么**；
- 于是 AP 上线的第一天，热路径就已经是快的，验收标准从一开始就是 §1 的性能指标。

★ **硬规则（可静态检查）** ★

> **热路径上不允许获取全局锁。** 热路径 = syscall 入口/出口、调度切换、
> IPC 收发、时钟中断。
>
> 落地：全局锁在定义处打标（`FE_LOCK_GLOBAL`）；调试构建里维护一个
> "本 CPU 是否在热路径上"的标志，任何在热路径中获取全局锁的行为
> **立即报错并打印调用点**。

这条规则把"性能优"从愿望变成**编译期/运行期可检查的约束**——
否则半年后有人为了改一个边角 bug，在半热路径上顺手加一把全局锁，
而性能的退化不会有任何测试报出来。

## 14. 明确不做，以及风险表

**不做**（每一条都有理由，不是"以后再说"）：

| 不做 | 理由 |
|---|---|
| NUMA 感知 | 虚拟机与目标硬件都没有 NUMA；现在做是凭空增加复杂度 |
| CPU 热插拔 | 没有使用场景；它要求每 CPU 数据结构可动态回收，会污染所有设计 |
| PCID / INVPCID | ~~不做~~ → **做**，但排在 TLB 正确性之后（§8）；性能优先下它是 fastpath 的配套项 |
| 无锁数据结构 | 除了引用计数与原子所有权，其它地方自旋锁足够；无锁化会带来内存回收难题 |
| 大内核锁（BKL） | ~~先上后拆~~ → **一开始就不上**：热路径改成不共享之后它没有存在的理由（§13） |

**风险表**（按"发现难度 × 后果"排序）：

| 风险 | 后果 | 对策 |
|---|---|---|
| **伪共享** | 性能莫名不达标，且 profiling 看不出来 | 每 CPU 结构 64 字节对齐；热字段与统计字段分开；G1 不达标时先查这个 |
| **中断里拿锁 → 同 CPU 自死锁** | 偶发挂起，测试难复现 | 规则 1 + 调试期"ISR 只准拿标了 IRQ 的锁"断言 |
| **双重执行**（同一线程两个核上跑） | 栈互相踩、随机崩溃 | 就绪→运行的转移必须原子；加"每线程 running_cpu"断言 |
| **`hlt` 唤醒丢失** | 偶发几百毫秒延迟尖刺（不是死锁） | 跨核入队必跟 reschedule IPI；空转前先查队列 |
| **时间变成 N 倍速** | sleep 变短、超时全错 | 节拍降级为每 CPU 调度输入，时间走 TSC（§7） |
| **PMM/kheap 无锁** | 内存随机损坏 | ★ **M10.1 就要修** ★：per-CPU slab 缓存 + 页帧批次（这不只是"加锁"，是把分配路径变成不共享的——见 `07-performance-roadmap.md` §5） |
| **锁顺序反转** | 死锁 | 层级表 + 调试期检测（死锁现场没有信息） |
| **"多核没生效"被静默接受** | 看起来做了，其实单核 | §10 的核数不一致必须报警；G1/G2 是硬指标 |
| **热路径被偷偷加回全局锁** | 扩展比从 3.5 掉到 1.5，但没有测试会报错 | §13 的硬规则：全局锁打标 + 热路径标志 + 调试构建直接报错 |
| **伪共享导致"看起来有锁"** | 明明没共享，扩展比仍然差 | G1 不达标时的第一诊断项：`perf` 看 HITM / 把每 CPU 计数器拆到独立 cache line |

## 15. 需要拍板的几件事

1. **目标核数**：2 / 4 / 8？决定 TSS 常驻内存（48 KiB/CPU）与
   "每 CPU 消息缓存"的规模。**性能口径下建议 4 核起**（G1 定在 3.5 需要至少 4 核
   才有意义），并且 8 核也要能跑（`--smp 8` 冒烟）。
2. **IPC fastpath 的钉核策略**（§11）：它用并行度换延迟，但性能优先的结论是
   **要做**——因为 IPC 固定成本里一大半是"经过调度器排队"。
   配套是"服务钉核 + 同一服务多副本各钉一核"，这同时给出 IPC 吞吐随核数扩展的路径。
3. **中断定向**：性能优先应当**直接按驱动线程所在核定向**（省一次跨核唤醒 +
   缓存局部性），不要经过"先全给 BSP"的中间态——那个中间态会让 G3 假达标。
4. **每 CPU slab / 页帧批次要不要在 M10.1 就做**：建议要。
   它既是 SMP 的正确性前提（今天 PMM/kheap 完全没同步），
   也是"分配路径不共享"这个性能目标本身——两件事一次做完。
5. **现有确定性自检怎么处理**：钉核保留（推荐）还是改成 SMP 感知的
   统计式断言？（这会影响今天日志里那条 `AAAAABBBBBCCCCC` 的输出含义。）

## 16. 与性能路线图的关系（再强调一次）

本文只负责多核这一格（3.5×）。**它不能替代 `07-performance-roadmap.md` 里的
主线 A（磁盘，1000×）与主线 D（SIMD，解锁一整类工作）**：

- 4 核跑在 182 KB/s 的磁盘上，A/B 更新从 7.6 秒变成 7.6 秒（I/O 是串行的）；
- 没有 SIMD，用户态连一个真正的密码学库都链不进来。

正确的执行顺序是：**批量共享内存 IPC → DMA 块设备 → fsd 缓存 → 多核 → fastpath → SIMD**。
前三条都不需要多核，但它们拿走了数量级级别的收益。
